# Three-view / all-type experiment

Stage=4 schedules the three native card preview slots **sequentially**. All card types with resolved metadata are eligible. The existing `Pick3NativeAvatarLoad` classifies fighter, environment, and other (trick/power) cards, and retains its in-hand sprite/static fallback.

The `RenderBudgetFps=60` setting is a shared total, not 60 per view. `SpacingFrames=45` staggers starts; the previous view must finish before the next starts.

## Button finding
The Choose control is generated by `Panel(...)`, with an optional stock `button_tint` sprite via `Pick3LocalAssetBundles::Sprite(6)`. The existing runtime log says `UNITYFS: CONFIG enabled=0 probeMode=0`, so the native button sprite **cannot** load. Native UnityFS mode 4 was not enabled because the source documents a native SIGSEGV risk. The neutral Choose panel + label + hit rect stay intact. This package does **not** claim to solve the missing stock button art.

## Test
Look for `ANIMATION_EXPERIMENT: CONFIG stage=4`; `AVATAR_LOAD: REQUEST option=1/2/3` or `SKIP` reasons; and `AVATAR_RENDER: UI_BOUND`. Tricks may render an in-hand sprite rather than a looping avatar. Verify choices are clickable and screen closes normally. If instability occurs revert `Stage=3` (or enable `NativeAvatarCrashIsolation=true`).
